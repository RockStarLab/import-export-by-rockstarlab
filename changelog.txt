== Content Sync, Media Sync, Import, Export with AI Agents Support: full changelog ==

= 2.2.13 =
* New: Import from URL accepts a Google Sheets link as you copy it from the browser or the Share dialog and downloads the sheet (the open tab) as CSV; a sheet that is not shared gets a message that explains how to share it.
* New: the AI Agent Connection wizard sets up Claude Desktop (configuration block or one command).
* New: user exports have a Custom Fields group (one column per profile field) and a User Meta (JSON) column.
* Fix: Content Sync to a site in a subfolder keeps cover image addresses correct.
* Fix: Content Sync waits for a connection that is busy instead of failing with "already in use".
* Fix: product categories and brands keep their images, upsells and cross-sells point to the right products, and downloadable files are copied with the product through Content Sync.
* Fix: Remote Comments show Pending, Spam or Trash next to comments that are not approved.
* Fix: the Primary Category column of Yoast SEO and Rank Math holds the category slug, and the import accepts a slug, a name or an ID of the receiving site.
* Fix: Yoast SEO shows imported category and tag titles and descriptions right away.
* Fix: changing a custom field filter condition in Export works again.
* Fix: images downloaded from post content by the import get the alt text of their image tag in the Media Library, when they have none yet.
* Fix: an import no longer stops with "Gateway Timeout" when one request times out (504, 502, 503, a dropped connection or a host error page): the wizard waits and tries again, up to six times, and the import continues where it stopped.
* Fix: the "Import failed" notice no longer shows "%s" before the error.
* Fix: Auto Map of an RSS feed maps pubDate to the post date and description to the excerpt (or to the content when the feed has no full text), and no longer maps link and guid to unrelated custom fields.

= 2.2.12 =
* Fix: Yoast SEO and Rank Math data (titles, robots, social images, primary category, category SEO) arrive complete through Content Sync and file export/import.
* Fix: the same image is no longer downloaded twice when its name has non-Latin letters.
* Fix: Content Sync to a multisite subsite keeps correct social image URLs.
* Fix: a clear message when the other site's PRO is not licensed.
* Fix: when the other site cannot be reached or its connection check failed, Content Sync says why and what to do instead of a raw cURL error; a file the other site refuses (for example SVG) is named in the message, and Job Details shows why a background sync failed.
* Fix: Trigger sources show readable content names; Debug Site Info shows the PRO version.

= 2.2.11 =
* Fix: Content Sync refuses a connection to the site itself, and an address without WordPress gets a clear message instead of "error status 405".
* Fix: the Content Sync sites list and the post screens no longer send the stored API keys of connected sites to the browser.
* Fix: Edit Site says that an empty API key keeps the current one, Test Connection no longer changes "Last Sync", and Escape closes the dialog.
* Fix: "Sync This Post" in the block editor saves your unsaved changes before it pushes; a pull over unsaved changes asks first.
* Fix: the WooCommerce orders screen with HPOS order storage has the Export button.
* Fix: the results of pulling terms, users, comments, menus, attributes and reviews, and of Media Sync, stay visible after the page reloads. Media Sync says how many files were copied and how many were already there.
* Fix: pushing a reply whose parent comment is not on the other site no longer fails; the reply arrives as a top-level comment. Push errors are shown in the push dialog.
* Fix: on multisite, deleting a site also removes the plugin's tables of that site. Before, they stayed and a new site with the same ID inherited them.
* Fix: Content Migration shows readable content names, names the package after the site and the date, explains why a ZIP file cannot be read, and enables "Start migration" only for a prepared package.
* Fix: choosing Custom Post Types or MySQL Database Table on the export screen no longer logs an error, and the Taxonomy Terms count waits for a taxonomy.
* Fix: the Jobs Log fits the screen without hiding the action buttons, and Job Details shows the file name instead of the server path.
* Fix: Restart in the Jobs Log runs a Content Sync again. Before, it created a job that waited forever. Product syncs are logged as products.
* Fix: Notifications keep your choices when an email address is not valid.
* Change: MySQL table export and import work with every table of the site, including the WordPress core tables.
* Change: FTP / SFTP Servers moved from the Jobs Log to Plugin Options.

= 2.2.10 =
* Fix: WP-CLI and AI agent imports of WordPress export (WXR) files now map titles, content, custom fields and terms. Before, such an import created nothing.
* Fix: WXR imports keep post passwords, the sticky flag and comment/ping settings, and the custom fields of every item (not only of the first previewed items). Several values of one custom field are all kept.
* Fix: product exports without chosen columns (WP-CLI, AI agents) now include the WooCommerce data: SKU, prices, stock, categories, attributes, variations and grouped products.

= 2.2.9 =
* Fix: Content Sync now carries a post's password, its comment and ping settings and the "sticky" flag, in both directions. Before, a password-protected post arrived public on the other site.
* Fix: post and page exports include the password and the comment and ping settings by default, so protected posts stay protected after an import on another site.

= 2.2.8 =
* Fix: Content Sync could leave the old site's media ID on Cover blocks with a fixed or repeated background, on images inside ACF WYSIWYG fields and on gallery images. The image the page shows now decides.
* Fix: repeating a sync or an import moved comment dates by the site's time zone offset every time.
* Fix: imports and site migrations that carry both the local and the GMT date of a post keep both, like the WordPress importer. Before, posts could show another date and time on the new site.
* Fix: Gallery blocks keep pointing at their images after a file import or a site migration.
* Fix: media files with non-Latin names (for example Cyrillic) keep their names in site migrations and media imports.
* Fix: importing comments after a Content Sync no longer adds the synced comments a second time.

= 2.2.7 =
* Fix: Excel (XLSX) and LibreOffice (ODS) exports cut every cell at 32,767 characters, the spreadsheet limit. Elementor pages and other long content lost their design and custom fields when such a file was imported. Longer values now continue in extra "…__part2" columns, which the import joins back.
* Fix: XML exports of pages built with Elementor stopped with "Export stopped unexpectedly", and keys with characters such as ":" or spaces were changed in XML files. Every key is now written so that it reads back exactly.
* Fix: re-importing pages from a file without a parent column no longer detaches them from their parent pages.
* Improved: post and page exports include the parent page and page order by default, so page trees and their order move with the file.
* Improved: comment exports include the GMT date, the author's website and the comment's custom fields (ACF) by default.
* Fix: Imported content now points File blocks, gallery images and images with non-Latin file names at the new site's media.
* Fix: Images in page-builder HTML keep their responsive sizes (srcset) after import.
* Fix: A child page imported on its own finds its parent from an earlier import.
* Fix: ACF image, file and gallery fields on comments are exported as files, not as attachment IDs of the old site.
* Fix: Content Sync could show the wrong image in a post when a new media ID on the receiving site matched another media ID of the sending site. Gallery images now also get the new media IDs.
* Fix: Images and files with non-Latin names (for example Cyrillic) are imported with their real names and are no longer skipped as invalid links.
* Fix: Custom fields with several values under one name (for example podcast enclosures) are imported as separate values again; before, they were merged into one value that grew with every export and import.
* Fix: XML exports keep empty lists inside theme and plugin settings (Blocksy, Stackable) as lists.
* Fix: imported and synced posts no longer send pingbacks to every site they link to, and WordPress no longer adds extra "enclosure" fields for linked audio and video files after an import (the same as the WordPress importer).

= 2.2.6 =
* Fix: importing comments from a file exported by this plugin skipped every comment since 2.2.4 (they were taken for WordPress export rows), and site migrations did not bring comments. Comment imports work again; only the post rows of a WordPress export (WXR) file are skipped.
* Improved: every ability that AI agents see now starts its description with what that ability does. Before, related abilities (schedules, functions, comment, review and term sync, WooCommerce push and pull, Content Updater) shared one text, and the term and review sync texts talked about comments.
* Fix: the list of jobs a schedule can be made from no longer starts a job's label with a dash when the job has no name.
* Fix: media files whose names contain non-Latin letters (for example Cyrillic) failed in media imports and migrations with "Local files can be imported only from the uploads folder".
* Fix: media imports and migrations now bring SVG files (icons and logos of Elementor sites), cleaned of scripts the same way as in Content Sync, when Elementor is active on the site. Before, WordPress refused them and migrated pages lost their icons.
* Fix: the migration step list no longer offers WooCommerce's internal order placeholders ("shop_order_placehold"); orders move with the order steps.
* Improved: pausing or cancelling a migration while it works on a batch now says to try again in a few seconds, instead of a generic "cannot continue" message.

= 2.2.5 =
* Fix: importing an exported file back into the same site with "Import media" off (the default for WP-CLI and AI agents) emptied every ACF image and file field and broke ACF galleries. Files that are already in this site's Media Library are now found by their URL without downloading anything; URL and text fields keep their URLs.
* Fix: WP-CLI imports without --mapping and AI agent imports (import-prepare) now map the ACF columns ("acf_…") of the file, like Auto Map in the admin. Before, ACF fields were filled from the raw custom fields of the other site, with its image, post and term IDs.
* Fix: media files with non-Latin letters in their names (for example Cyrillic) are found in the Media Library during imports instead of being downloaded again.
* Changed: the plugin name in the WP-CLI help, Site Debug Info and the PRO addon's Freemius screens is now "Content Sync, Media Sync, Import, Export with AI Agents Support".
* Fix: All Site URLs export listed sticky posts twice and could leave out other posts or terms of the same batch. The Shop page is listed once (WooCommerce's product archive is the same URL), and Elementor site settings records, which have no page, are left out.

= 2.2.4 =
* New: importing a WordPress export (WXR) file also creates the comments of each post and page, with replies in their threads, their status (approved, pending, spam) and pingbacks/trackbacks. A second import adds no duplicates.
* Fix: importing a WordPress export now keeps the category tree: the file's categories (and the terms of other mapped taxonomies) are created with their parents before the posts. Before, every category was created at the top level.
* Improved: posts from a WordPress export whose author login does not exist on this site go to the user with the same email (from the file's author list). No users are created.
* Fix: a Posts import of a WordPress export created its pages as posts too (and a Pages import the posts as pages). Each import now takes only its own type; skipped items are summarized in one note per kind instead of one per row.
* Fix: a Comments import of a WordPress export reported every post as a failed row. The rows are skipped with a note: the comments come with the Posts/Pages import.
* Fix: synced patterns and Query Loop categories in XML export files (new in 2.2.3) were not re-pointed on import. CSV, JSON and Excel files were not affected. Lists keyed by IDs in XML files keep their keys.
* Fix: importing a WordPress REST API JSON (/wp-json/wp/v2/posts): Auto Map now maps title, content and excerpt (the "rendered" values) and no longer maps the other site's post ID, author, featured media, categories, tags or links.
* Improved: the plugin name in the admin is now "Content Sync, Media Sync, Import, Export with AI Agents Support"; the Welcome page starts with Content Sync (and a typo in its header is fixed).
* Fix: Content Sync now carries the categories of synced patterns (created by slug on the other site when missing), and a pattern that is synced again on the source no longer stays "not synced" on the target.
* Fix: Media Sync and Content Sync now update the title, alt text, caption and description of a file that was synced before, when they change on the source site. Before, only the first sync carried them. Other files on the target that merely have the same bytes keep their own text.
* Fix: Content Sync: when the other site already had the same file under another name, File block download links, Cover, Media & Text and video URLs still pointed to the source file name (a broken link). They now point to the file actually used, like images already did.
* Improved: Content Sync no longer uploads large files again (videos and other files over 16 MB) that the other site already has. A page with a 28 MB video re-synced in 30 s instead of 64 s.
* Fix: images and files whose names contain non-Latin letters (for example Cyrillic) were not matched to the existing Media Library file during imports run from WP-CLI or cron and in some Content Sync URL checks. The URL path is now kept exactly as written.
* Fix: Content Sync: a child page pushed or pulled before its parent stayed at the top level, even after the parent was synced. It is now attached to the parent when the parent arrives (unless you chose another parent on that site in the meantime).

= 2.2.3 =
* Changed: the plugin is now called "Content Sync, Media Sync, Import, Export with AI Agents Support" (formerly Import Export by RockStarLab). Same plugin, settings and updates; Content Sync is now first in the admin menu.
* Fix: Migration through the Abilities API / MCP (migration-prepare) failed with "invalid output" since 2.2.2. The admin wizard was not affected.
* Fix: Importing a WordPress export (WXR) file now brings featured images (from the image items in the same file) and custom fields ("Meta: …" columns that Auto Map maps), including Elementor designs. WordPress bookkeeping fields are left out.
* Fix: The XML import wizard listed only the columns of the first record. A WordPress export starts with its images, so categories, tags, featured image and custom fields were missing from Field Mapping. Columns now come from the first 50 records.
* Fix: Pages from a WordPress export (or any file with wp:post_parent / post_parent IDs) were attached to unrelated pages on the new site. They are now attached to the imported copy of their parent, even when the child comes first in the file.
* Fix: Posts using synced patterns or a Query Loop filtered by category showed "This block has been deleted or is unavailable" (or the wrong category) after a file import or migration to another site. The file now carries the patterns and terms; the import creates or matches them and re-points the blocks. Images inside the patterns are downloaded too.
* Fix: ACF Clone fields shown as a group (with or without prefixed names), also inside repeaters and flexible content layouts, are now exported and imported. Before, their values were lost or written over another field.
* Fix: Media import of a WordPress export: posts and pages in the file are skipped instead of reported as failed rows, Auto Map maps the file address, and each file is attached to the post imported from the same source post (not to an unrelated post with the same ID).

= 2.2.2 =
* Security: serialized PHP objects in import data are no longer turned into objects (PHP object injection through post meta, ACF, SEO and Elementor values).
* Security: a media import row with a local file path can only use files from allowed import folders. Before, any readable server file could be copied into the Media Library.
* Fixed: PRO Content Updater and ACF: see Import Export PRO 2.1.21; the shared ACF importer now keeps relationship, post object, taxonomy and user values (also from spreadsheet cells: slugs, titles, term names, logins) and ACF Clone fields.
* Fixed: importing the plugin's own CSV or Excel export kept no custom fields (ACF, Elementor data, SEO meta), because the post_meta column was ignored.
* Fixed: ACF on import, migration and sync. Re-importing an unchanged ACF value no longer writes the source site's IDs over it. Linked images inside WYSIWYG fields are re-hosted. [gallery] IDs inside ACF HTML point to the right images. A "Replace links" rule no longer empties ACF images. Relationship and Post Object values on users, terms, comments, media, products and menus are kept, also inside repeaters, groups and flexible content.
* Fixed: an export no longer removes other plugins' database query filters for the rest of the request (ACF's field lookup among them).
* Fixed: CSV files with Mac line endings, blank lines or a blank line above the header; Excel and LibreOffice dates, formulas, empty top rows and the table on a second sheet; JSON Lines and other JSON shapes; deeply wrapped XML records and XML attributes; files with the wrong extension.
* Fixed: post import. Authors given by login, email or name; Unix timestamps; update by slug finds drafts; parent given by slug, path or title; untitled posts from a full export; update files with no title column no longer create empty posts.
* Fixed: WordPress export (WXR) files. Media items, revisions and menu items in the file are skipped with a note instead of becoming empty posts.
* Fixed: comment import dates, duplicate spam/trash comments on re-import, media "Attached Post Title".
* Fixed: number filters in Filter Rows compare numbers ("$25.50", "1,234.5", "12,5 €").
* Fixed: Content Sync. Backslashes and CSS variables in content are kept; empty block attributes stay {}; links keep the other site's port and path on pull; a featured image that could not be sent no longer leaves a foreign ID; SVGs are not duplicated on round trips; images and SVG icons inside Elementor repeaters (Icon List, slides, carousels) are sent; synced patterns, navigation menus and Query Loop / Latest Posts categories are carried and re-pointed, with the images inside patterns.
* Fixed: Content Sync speed. Media capabilities are negotiated once per sync, and new images no longer cost one request per thumbnail size.
* Fixed: Content Migration. Site migration carries ACF values portably; a package with PRO content opens on a site without a PRO license (those parts are skipped with a note); a media file the site does not accept (such as SVG) no longer stops the whole migration.
* Fixed: Media Library sync in list view sends the rows you tick.
* Fixed: export. Comment type filter, parent page filter, stable order of items with the same date, large JSON/XML/Excel exports no longer run out of memory, the Jobs Log shows the real export duration.
* Fixed: admin. "[object Object]" error notices; an error on the ACF Categories/Tags screens; empty browser tab titles on some plugin screens; a "-1-day free trial" banner on sites that skipped opt-in.
* Fixed: Content Sync dialog. The success message stays on screen (no more empty dialog with only its title); a push from the block editor no longer reloads the editor; posts synced before (also drafts) show "Update" instead of "Create New Post".

= 2.1.38 =
* Fixed: when the file of a "file changes" trigger changed again while the trigger's previous job was still running, the change could be skipped. The next hourly check now starts the import.
* Improved: the Triggers list shows post type names, the wait time in minutes, and the number of runs in correct English.

= 2.1.37 =
* New: event triggers (Jobs Log → Triggers). Run a finished import or export again when another system calls a secure webhook URL (Zapier, Make, n8n, a CRM or a script), when a post of chosen types is published, when a WooCommerce order is created, or when the file an import downloads from a URL changes (checked hourly). Each run is a new job with the same file source, mapping and options, started as the administrator who created the trigger.
* New: webhook triggers use a secret token sent in the X-RSL-Token header or as a Bearer token, never in the URL. The token is shown once, stored only as a hash and can be replaced at any time. Repeated wrong tokens are blocked for an hour.
* New: triggers never start a second job while the previous one is still running, webhook runs are limited to one a minute, and post and order events within the chosen wait time start a single run. Posts created by the plugin's own imports, syncs and migrations do not start triggers.
* New: AI agents can list, create, pause, run and delete triggers, replace a webhook token and read the trigger log (rsl-ie/trigger-sources, trigger-list, trigger-get, trigger-create, trigger-update, trigger-run, trigger-rotate-token, trigger-delete, trigger-log).
* Improved: uninstalling the plugin also removes mapping templates, notification settings and triggers.

= 2.1.36 =
* Fixed: a custom field added in the Field Mapping step with a plain key such as "event_id" was not saved by the import. Keys without a meta_ or _ prefix now get meta_ automatically, and custom fields stored under an underscore key (for example _event_code) can be used to find existing posts.
* Improved: the "Or import a file from a URL" box is hidden while a file is uploading and after it is uploaded, and comes back when you remove the file.
* Improved: the mapping template list in step 4 shows "Loading templates…" until the saved templates are loaded, and Load Template and Save as Template show that they are working.

= 2.1.35 =
* New: field mapping templates. Save the column mapping and import settings of an import under a name ("Save as Template" in steps 4 and 5) and load it for the next file in step 4. Columns are matched by name, so their order may change; columns missing from the new file are listed and their fields highlighted. Templates can be renamed and deleted, and any earlier import can be saved as a template from the Jobs Log.
* New: AI agents can list, read, save, delete and apply mapping templates (rsl-ie/mapping-template-list, -get, -save, -delete, -from-job, -apply). mapping-template-apply returns a mapping and options that import-start accepts unchanged.
* Fixed: an import of posts, pages or custom post types with a custom field as "Check for Existing Items by Field" (for example a supplier code) created a new post every time instead of updating the matching one. Custom fields (meta_ and acf_ columns) now work as the match key, and the list offers only fields an existing post can be found by.
* New: notifications when a job finishes (Jobs Log → Notifications): email, a Slack channel, or a signed webhook (JSON with HMAC-SHA256 signature) for Zapier, Make, n8n or your own system. Choose after every job or only when something failed, and which jobs (imports, exports, Content Sync, Content Migration); edit the subject and message with placeholders. Failed webhook and Slack deliveries are retried, at most 30 notifications are sent per hour, and the screen lists recent deliveries.
* New: readable import errors. Each failed row shows the row number in the file, the field, the error and how to fix it, on the import result screen and in the Jobs Log details. "Download rows with errors (CSV)" saves the failed rows with their values, ready to correct and import again.
* New: AI agents can read and change notification settings, send a test and read the delivery log (rsl-ie/notification-settings-get, -update, notification-test, notification-log), and read the failed rows of an import with fixes and the error CSV (rsl-ie/job-errors).

= 2.1.34 =
* Fixed: importing a damaged ZIP file no longer writes a "Zip stream error: CRC error" PHP warning to the site's error log; the import reports the file as damaged.
* Improved: the Taxonomy Filter of the export screen accepts term names, slugs or IDs, and taxonomy names such as "Categories" or "Tags". Before, only slugs worked, so a category whose slug differs from its name (for example "edge-case-2") was not found.
* New: "Category Names" and "Tag Names" export columns: plain comma-separated names that are easy to read and filter in a spreadsheet. The existing category and tag columns keep the full term data for imports.
* Fixed: an export or preview requested with the field list "*" (as AI agents often do) produced a single empty "*" column. It now exports the default columns.
* New: media export columns "Original File Size" and "Size on Disk, All Sizes". WordPress keeps the original of a large upload next to a scaled-down copy and creates several smaller sizes; these columns show how much space each image really takes.
* Fixed: a Media import set to update existing files stopped with "File source is required" when the file had no file URL column. You can now update alt text, titles, captions and descriptions of existing Media Library items by ID (or another unique field) without the files.

= 2.1.33 =
* New: "Parent Title" export column for posts and pages: the title of the parent page next to its ID, empty for top-level pages.
* Improved: Auto-match by Title no longer stops when one title exists on several posts of the remote site. The other posts are matched, and only those rows are left for you to choose, with a message naming the title. AI agents get the same result: the post appears in "ambiguous" with the IDs of the remote posts to choose from.
* Improved: the remote post list in Map Posts for Sync shows the status and date of each post, so posts with the same title can be told apart.
* Fixed: searching the remote post list right after opening it could show "The results could not be loaded" while the first search was still running. The search now waits and retries.
* Fixed: remote post titles in the Map Posts for Sync list are always shown as plain text, and titles with & or other special characters are shown correctly.
* Fixed: an AI agent that renamed a post and then ran Auto-match in the same session could get a match for the old title. Auto-match and the selected-posts list now read the current titles.
* Fixed: Content Sync now sends files that a post links to, such as a PDF in a link, a File block, or a video or audio file, together with the post. Before, the link was changed to the target site but the file was not copied there.
* Fixed: "Last Sync" on the Content Sync screen now shows the time of the last completed push or pull. Before, it changed only when the connection was tested.
* Fixed: CSV, XLSX and ODS exports started by AI agents or other API calls without the header option had no header row. The header row is now included unless it is turned off, as in the export screen.

= 2.1.32 =
* Fixed: pulling a post back to the site it was first pushed from could add a second copy of its comments. Comments that already exist on the post (same author email, date and text) are now matched instead of added again.

= 2.1.31 =
* Improved: XLSX and ODS exports write plain numbers (such as 120, 0.5 or -12) as number cells you can sort and sum, and keep codes with leading zeros (00123), numbers longer than 11 digits (barcodes, tracking numbers) and values like 49.90 as text, so spreadsheet apps don't change them.
* Improved: AI agents can use the same CSV separators as the export screen in rsl-ie/export-start, including multi-character separators of up to 10 characters such as ;; or |~|.

= 2.1.30 =
* New: "Changes only" for scheduled exports of posts and pages. The first run exports everything the filters select; each later run exports only what was modified since the previous completed run started. Also available to AI agents as changed_only in the schedule abilities.
* Improved: a Date or Modified Date filter with a time (for example 2026-11-09 08:30) now compares to the minute instead of the whole day.
* Improved: background exports (scheduled runs and exports started by AI agents) process several batches per cron event. A scheduled export of 74 posts in batches of 3 needed about 25 cron events before; now it finishes in one.
* Improved: exports with filters are much faster on large sites. The posts that match are found once per export instead of once per batch, and Status and Date filters are applied by the database: on a site with 100,000 posts the item counter with a Status filter takes 0.07 s instead of 5.5 s, and each batch after the first 0.1 s instead of 5 s.
* Improved: the default export batch size is 50 instead of 3, and the field accepts up to 500 (the largest value the exporter uses). A 100,000-post export in the browser took about 70 minutes with batches of 3 and about 3 minutes with 500.
* Fixed: a CSV export of a very large site (100,000 posts with content) stopped at the end with a PHP memory error, because the whole file was built in memory. CSV files are now written row by row.
* Fixed: a Content Sync push started from a long-running process (an AI agent through the stdio MCP server, or WP-CLI) could send an older copy of a post that had been edited in the meantime. The selected posts are now read fresh before every push.

= 2.1.29 =
* New: "UTF-8 BOM" option for CSV exports, so Excel shows accented letters and emojis correctly. Also available to AI agents as format_options.csv_use_bom.
* Improved: the Content Sync connection test explains why a connection fails: a wrong or not yet activated API key, a firewall page (HTTP 403), HTTP authentication on a staging site, a redirect to another address (with the address to use), a REST API blocked by a plugin (with its error code), or no REST API at the address.
* Improved: a site address pasted with /wp-admin/ or /wp-login.php is saved as the site's home address, and a connection is marked Active again after its key or address is fixed.
* Improved: the Abilities API connection-test and connection-create abilities return the same explanation instead of a generic failure.
* Improved: Auto-match by Title for large selections lists the remote posts once per post type instead of searching for every post. 150 posts are matched in seconds instead of minutes.
* Improved: queuing a background sync while another transfer uses the same connection explains that the connection is busy instead of a generic message.
* Improved: Jobs Log shows background sync jobs as "Content Sync - Background".
* Fixed: the Test Connection button showed only "Connection test failed" instead of the reason. Other Content Sync notices also show the server's message now.
* Fixed: Content Sync works with sites that use plain permalinks (no /wp-json/ path).
* Fixed: plugins that limit the REST API to logged-in users (such as Disable WP REST API) no longer block Content Sync requests signed with the site key.
* Fixed: a Content Sync push or pull started from the Posts or Pages screen could not be picked as the source of a schedule (only pushes started by an AI agent could).
* Fixed: the Confirm & Sync button stays disabled while Auto-match by Title is running, so a push can't start while the connection is still busy.
* Fixed: when Auto-match by Title fails (for example, two remote posts with the same title), the reason is shown and the rows keep their choices instead of switching to Create New Post. The message names the title.
* Fixed: a long Content Sync push or pull was shown as Failed ("Invalid job type") in Jobs Log while it was still running. A sync request that stopped without finishing (server time limit) is now marked Failed after two hours with advice to sync the rest in smaller batches.
* Fixed: a custom CSV delimiter with more than one character (such as ;; or |~|) stopped the export. Custom delimiters of up to 10 characters work now.

= 2.1.28 =
* New: rename any export column with the pencil icon, so the file uses the column names another system expects, for example Google Merchant Center attributes (id, title, price, availability).
* New: custom export columns ("Add Custom") can hold a fixed value for every row, for example condition = new. Before, a custom column was left out of the file.
* New: the WooCommerce product export has the option "One row per variation" for product feeds. Each variable product is replaced by its enabled variations with their own SKU, price, stock, image and link, and the new Parent SKU column groups them.
