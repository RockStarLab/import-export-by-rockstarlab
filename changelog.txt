== Import Export by RockStarLab: full changelog ==

= 2.1.35 =
* New: field mapping templates. Save the column mapping and import settings of an import under a name ("Save as Template" in steps 4 and 5) and load it for the next file in step 4. Columns are matched by name, so their order may change; columns missing from the new file are listed and their fields highlighted. Templates can be renamed and deleted, and any earlier import can be saved as a template from the Jobs Log.
* New: AI agents can list, read, save, delete and apply mapping templates (rsl-ie/mapping-template-list, -get, -save, -delete, -from-job, -apply). mapping-template-apply returns a mapping and options that import-start accepts unchanged.
* Fixed: an import of posts, pages or custom post types with a custom field as "Check for Existing Items by Field" (for example a supplier code) created a new post every time instead of updating the matching one. Custom fields (meta_ and acf_ columns) now work as the match key, and the list offers only fields an existing post can be found by.
* New: notifications when a job finishes (Jobs Log → Notifications): email, a Slack channel, or a signed webhook (JSON with HMAC-SHA256 signature) for Zapier, Make, n8n or your own system. Choose after every job or only when something failed, and which jobs (imports, exports, Content Sync, Content Migration); edit the subject and message with placeholders. Failed webhook and Slack deliveries are retried, at most 30 notifications are sent per hour, and the screen lists recent deliveries.
* New: readable import errors. Each failed row shows the row number in the file, the field, the error and how to fix it, on the import result screen and in the Jobs Log details. "Download rows with errors (CSV)" saves the failed rows with their values, ready to correct and import again.
* New: AI agents can read and change notification settings, send a test and read the delivery log (rsl-ie/notification-settings-get, -update, notification-test, notification-log), and read the failed rows of an import with fixes and the error CSV (rsl-ie/job-errors).

= 2.1.34 =
* Fixed: importing a damaged ZIP file no longer writes a "Zip stream error: CRC error" PHP warning to the site's error log; the import reports the file as damaged.
* Improved: the Taxonomy Filter of the export screen accepts term names, slugs or IDs, and taxonomy names such as "Categories" or "Tags". Before, only slugs worked, so a category whose slug differs from its name (for example "edge-case-2") was not found.
* New: "Category Names" and "Tag Names" export columns: plain comma-separated names that are easy to read and filter in a spreadsheet. The existing category and tag columns keep the full term data for imports.
* Fixed: an export or preview requested with the field list "*" (as AI agents often do) produced a single empty "*" column. It now exports the default columns.
* New: media export columns "Original File Size" and "Size on Disk, All Sizes". WordPress keeps the original of a large upload next to a scaled-down copy and creates several smaller sizes; these columns show how much space each image really takes.
* Fixed: a Media import set to update existing files stopped with "File source is required" when the file had no file URL column. You can now update alt text, titles, captions and descriptions of existing Media Library items by ID (or another unique field) without the files.

= 2.1.33 =
* New: "Parent Title" export column for posts and pages: the title of the parent page next to its ID, empty for top-level pages.
* Improved: Auto-match by Title no longer stops when one title exists on several posts of the remote site. The other posts are matched, and only those rows are left for you to choose, with a message naming the title. AI agents get the same result: the post appears in "ambiguous" with the IDs of the remote posts to choose from.
* Improved: the remote post list in Map Posts for Sync shows the status and date of each post, so posts with the same title can be told apart.
* Fixed: searching the remote post list right after opening it could show "The results could not be loaded" while the first search was still running. The search now waits and retries.
* Fixed: remote post titles in the Map Posts for Sync list are always shown as plain text, and titles with & or other special characters are shown correctly.
* Fixed: an AI agent that renamed a post and then ran Auto-match in the same session could get a match for the old title. Auto-match and the selected-posts list now read the current titles.
* Fixed: Content Sync now sends files that a post links to, such as a PDF in a link, a File block, or a video or audio file, together with the post. Before, the link was changed to the target site but the file was not copied there.
* Fixed: "Last Sync" on the Content Sync screen now shows the time of the last completed push or pull. Before, it changed only when the connection was tested.
* Fixed: CSV, XLSX and ODS exports started by AI agents or other API calls without the header option had no header row. The header row is now included unless it is turned off, as in the export screen.

= 2.1.32 =
* Fixed: pulling a post back to the site it was first pushed from could add a second copy of its comments. Comments that already exist on the post (same author email, date and text) are now matched instead of added again.

= 2.1.31 =
* Improved: XLSX and ODS exports write plain numbers (such as 120, 0.5 or -12) as number cells you can sort and sum, and keep codes with leading zeros (00123), numbers longer than 11 digits (barcodes, tracking numbers) and values like 49.90 as text, so spreadsheet apps don't change them.
* Improved: AI agents can use the same CSV separators as the export screen in rsl-ie/export-start, including multi-character separators of up to 10 characters such as ;; or |~|.

= 2.1.30 =
* New: "Changes only" for scheduled exports of posts and pages. The first run exports everything the filters select; each later run exports only what was modified since the previous completed run started. Also available to AI agents as changed_only in the schedule abilities.
* Improved: a Date or Modified Date filter with a time (for example 2026-11-09 08:30) now compares to the minute instead of the whole day.
* Improved: background exports (scheduled runs and exports started by AI agents) process several batches per cron event. A scheduled export of 74 posts in batches of 3 needed about 25 cron events before; now it finishes in one.
* Improved: exports with filters are much faster on large sites. The posts that match are found once per export instead of once per batch, and Status and Date filters are applied by the database: on a site with 100,000 posts the item counter with a Status filter takes 0.07 s instead of 5.5 s, and each batch after the first 0.1 s instead of 5 s.
* Improved: the default export batch size is 50 instead of 3, and the field accepts up to 500 (the largest value the exporter uses). A 100,000-post export in the browser took about 70 minutes with batches of 3 and about 3 minutes with 500.
* Fixed: a CSV export of a very large site (100,000 posts with content) stopped at the end with a PHP memory error, because the whole file was built in memory. CSV files are now written row by row.
* Fixed: a Content Sync push started from a long-running process (an AI agent through the stdio MCP server, or WP-CLI) could send an older copy of a post that had been edited in the meantime. The selected posts are now read fresh before every push.

= 2.1.29 =
* New: "UTF-8 BOM" option for CSV exports, so Excel shows accented letters and emojis correctly. Also available to AI agents as format_options.csv_use_bom.
* Improved: the Content Sync connection test explains why a connection fails: a wrong or not yet activated API key, a firewall page (HTTP 403), HTTP authentication on a staging site, a redirect to another address (with the address to use), a REST API blocked by a plugin (with its error code), or no REST API at the address.
* Improved: a site address pasted with /wp-admin/ or /wp-login.php is saved as the site's home address, and a connection is marked Active again after its key or address is fixed.
* Improved: the Abilities API connection-test and connection-create abilities return the same explanation instead of a generic failure.
* Improved: Auto-match by Title for large selections lists the remote posts once per post type instead of searching for every post. 150 posts are matched in seconds instead of minutes.
* Improved: queuing a background sync while another transfer uses the same connection explains that the connection is busy instead of a generic message.
* Improved: Jobs Log shows background sync jobs as "Content Sync - Background".
* Fixed: the Test Connection button showed only "Connection test failed" instead of the reason. Other Content Sync notices also show the server's message now.
* Fixed: Content Sync works with sites that use plain permalinks (no /wp-json/ path).
* Fixed: plugins that limit the REST API to logged-in users (such as Disable WP REST API) no longer block Content Sync requests signed with the site key.
* Fixed: a Content Sync push or pull started from the Posts or Pages screen could not be picked as the source of a schedule (only pushes started by an AI agent could).
* Fixed: the Confirm & Sync button stays disabled while Auto-match by Title is running, so a push can't start while the connection is still busy.
* Fixed: when Auto-match by Title fails (for example, two remote posts with the same title), the reason is shown and the rows keep their choices instead of switching to Create New Post. The message names the title.
* Fixed: a long Content Sync push or pull was shown as Failed ("Invalid job type") in Jobs Log while it was still running. A sync request that stopped without finishing (server time limit) is now marked Failed after two hours with advice to sync the rest in smaller batches.
* Fixed: a custom CSV delimiter with more than one character (such as ;; or |~|) stopped the export. Custom delimiters of up to 10 characters work now.

= 2.1.28 =
* New: rename any export column with the pencil icon, so the file uses the column names another system expects, for example Google Merchant Center attributes (id, title, price, availability).
* New: custom export columns ("Add Custom") can hold a fixed value for every row, for example condition = new. Before, a custom column was left out of the file.
* New: the WooCommerce product export has the option "One row per variation" for product feeds. Each variable product is replaced by its enabled variations with their own SKU, price, stock, image and link, and the new Parent SKU column groups them.
* New: exports with the Tab delimiter are saved as .tsv files.
* Improved: Auto Map recognizes common review export headers (Review ID, Reviewer Name, Reviewer Email, Rating, Review Date, Verified Buyer, Reply To and others), more product export columns (children, sale price dates), and no longer maps gallery video columns to the image gallery.
* Improved: a reviews export can include the Parent Review ID, so replies stay under their reviews on another store.
* Fixed: the import result no longer says "Import Failed" when rows were skipped on purpose.
* Fixed: the Tab option in the CSV delimiter list showed a double backslash.

= 2.1.27 =
* New: import a file from a URL. Paste the address of a CSV, XML, JSON, XLSX or ODS file below the upload area and click Fetch File; the server downloads and checks it like an upload. When the import is repeated by a schedule, the file is downloaded again on every run, so supplier price lists and feeds stay current.
* New: XML imports read product and data feeds from other systems, not only the plugin's own files. The repeating element is found automatically (<product>, <item> in RSS and Google Merchant feeds, <offer>, and so on). Attributes become their own columns (price@currency), lists such as <images><image> become one comma-separated column, nested elements get path names (shipping/weight) and namespaced fields keep their prefix (g:price).
* Improved: the Taxonomy Terms export and import screens have an "Image URL" field for term images such as WooCommerce category thumbnails, and the import screen has "Parent Slug or Name". Auto Map recognizes Image, Thumbnail, Parent Category and Parent Name columns.
* Fixed: a term import from a spreadsheet without term IDs now sets the parent of a category even when the parent comes later in the file. The parent can be given as a slug or as a name.

= 2.1.26 =
* Improved: WooCommerce order export and import screens offer a "Tax Lines (Array)" field. It holds each tax rate of the order with its label, rate and amounts, so the PRO order import can rebuild the same tax lines on another store.

= 2.1.25 =
* Improved: Auto Map recognizes common customer spreadsheet columns: Address, Address 2, City, State or Province, Zip or Postcode, Country, Phone, Company and Customer Since.
* Improved: WooCommerce customer billing and shipping fields have capitalized names on the export and import screens ("Billing City" instead of "billing city").

= 2.1.24 =
* Improved: Auto Map maps a "Status" column to Status and "Type" to Product Type. Before, "Status" could land in Comment Status, and a "Weight Unit" column in Weight.
* Fixed: importing posts and pages with Status values such as TRUE, FALSE, active or archived now sets a real WordPress status (published or draft). Values WordPress does not know are ignored, so the default status is used and an update keeps the current one. The same applies to Comment Status and Ping Status (yes/no, 1/0, open/closed).
* Developer: new filter rsl_ie_import_file_prepared lets an add-on convert an uploaded file into the native column layout before preview and mapping. The upload step shows what was converted (used by PRO for Shopify product and customer exports).

= 2.1.23 =
* Fixed: pushing a WooCommerce product with Content Sync no longer replaces the receiving store's stock quantity, stock status, sales count or ratings. These values belong to the store that takes the orders. A product created by the push still gets the stock from the sending site.
* Fixed: pushing to a site that was cloned from the sending site no longer duplicates comments and reviews that both sites already have.
* Fixed: importing a file with a Permalink column (for example a file exported by this plugin) no longer changes post slugs. Auto Map maps Permalink to Slug; the importer now takes the slug from the end of the URL.
* Fixed: an update import that only changes custom fields (for example SEO titles and meta descriptions) no longer sets the post's "Last modified" date to the import time.

= 2.1.22 =
* Fixed: in Export > Export Format, clearing "Pretty Print" (JSON, XML) or "Include Header Row" (CSV, XLSX, ODS) now takes effect. Before, the file was always indented and always had a header row.

= 2.1.21 =
* Fixed: an import that stops before processing any row (for example, because the file matches by ID and an ID belongs to another content type) now shows an "Import Failed" result with the reason instead of staying on "Preparing import...".
* Improved: when matching by ID, the error for an ID that belongs to another content type now explains what to change.

= 2.1.20 =
* Fixed: in Export > Filter Data, a Custom Field (Meta) filter now labels its first input "Custom field name" instead of "Select Field...".

= 2.1.19 =
* Fixed: importing posts or pages in update mode now changes only the columns in the file. Status, author, comment status and other fields that are not mapped keep their current values instead of being reset to the import defaults. New posts created by the import still use the defaults.
* Improved: in update mode matched by ID or slug, the file no longer needs a title column, so a file with only ID and one meta field (for example a Yoast meta description) can be imported.

= 2.1.18 =
* Fixed: GitHub Copilot in VS Code can connect to the site through MCP Adapter. VS Code does not send the MCP-Protocol-Version header after the first request, and MCP Adapter rejected the session with "MCP-Protocol-Version header is required". When the header is missing, the plugin now fills in the protocol version already negotiated for that session. A header the client sends is never changed, and requests without a valid session are still rejected.

= 2.1.17 =
* Fixed: the one-command setup for Claude Code and Gemini CLI in Plugin Options > AI Agent Connection now puts the server name and address before the authorization header, so the generated command is accepted by current versions of both tools.
* Improved: export Abilities accept common spellings of filter conditions (greater_than, less_than, gte, lte, not_equal and similar) and reject an unknown condition with a list of the supported ones, instead of ignoring the filter.
* Improved: file-preview explains that export files cannot be previewed and points to file-get and export-preview.

= 2.1.16 =
* Added: Permalink and Word Count columns for post and page exports (Standard group), for content inventories and audits. Word Count counts the words of the content without HTML tags and shortcodes.

= 2.1.15 =
* Fixed: an ACF image or file field filled from a spreadsheet cell with one address now imports the file when the address has no file extension (image.php?id=42), contains spaces, or points to a PDF or another document on a different host.

= 2.1.14 =
* Improved: imports with many images stay fast as the Media Library grows. The duplicate check for each downloaded image now uses an exact lookup of the stored file hash, and images without a stored hash are indexed once per request instead of on every check. 10,000 posts with featured images and ACF fields imported in about 27 minutes on a local test site.
* Fixed: ACF post object, relationship and page link values that point to a post further down the same file were left empty. They are now resolved when the import finishes, including values inside repeaters and flexible content.
* Improved: the transformation preview on the export screen labels the original value.

= 2.1.13 =
* Improved: large imports keep a steady speed from the first row to the last. A 100,000-row CSV with categories and tags imported in about 80 minutes on a local test site, with about 20 MB of memory per request.
* Improved: preparation of large files reads up to 1,000 rows per request, and the per-request check for source file changes uses a much faster checksum. The full file is still verified before the first row is imported.
* Improved: duplicate checks by title run once per batch, and category and tag counts are updated once per batch instead of after every post.
* Improved: a batch stops after about 20 seconds and continues in the next request, and does not start a row that is unlikely to finish in time, so a large Batch Size no longer risks request timeouts. The default Batch Size is now 50 (5 for media library files).
* Improved: with the browser tab closed, each background (WP-Cron) run keeps importing for up to about 20 seconds instead of a single batch.
* Improved: the job result keeps exact counters, the latest 200 rows and up to 500 error messages, so its size no longer grows with the number of rows.
* Added: ACF gallery cells can list image URLs separated by commas or "|", and IDs of existing Media Library images.
* Added: spreadsheet-friendly values for ACF fields: lists for multi-select and checkbox, choice labels, yes/no for true/false, dates in common formats or the field's own format, terms by name, slug or ID, users by login, email or ID, posts by ID, slug, title or URL, a plain URL for link fields and a Dashicons name for icon picker fields.
* Fixed: ACF fields registered in PHP or acf-json were exported as display values (formatted dates, oEmbed HTML, link URL only), which did not import back. They are now exported like fields stored in the database.
* Fixed: flexible content sub-fields were missing from exports when the layout array keys differed from the layout keys.

= 2.1.12 =
* Fixed: taxonomy fields added with "+ Add" on the import mapping step (for example category or post_tag) were ignored during the import, so posts kept only the default category while the import reported success. Mappings saved this way earlier work again.
* Fixed: Auto Map did not map "categories", "category", "tags" and "tag" columns when importing blog posts. They are now mapped to the category and tag taxonomies.
* Added: "Parent > Child" values create or reuse nested terms in hierarchical taxonomies, such as categories, with any number of levels.
* Added: terms in one cell can be separated with "|" as well as with commas.
* Fixed: when several columns were mapped to the same taxonomy, only the last column was imported. Their terms are now combined.

= 2.1.11 =
* Fixed: featured images given by URL in an import file were only downloaded when they came from another WordPress site's uploads folder. Images from any http(s) address (a CDN, an image service, a shop) are now imported, including addresses with a query string, without a file extension or behind a redirect.
* Fixed: image addresses with spaces or accented characters in the file name, as they are often typed in spreadsheets, were skipped. They are now encoded and imported.
* Fixed: a featured image that could not be downloaded was only noted in the Jobs Log while the import reported success. It is now listed on the result screen with the row and the reason, such as "Download failed with HTTP 404" or "The address did not return an image file".
* Improved: with Automatically Import Media Files on, images inside the post text are also downloaded from other hosts when their address ends in an image extension. Gravatar avatars and WordPress emoji images are left alone.
* Added: a Featured Image Alt Text field (featured_image_alt) for import and export, so alt text can be set from a spreadsheet column.
* Added: Excel =HYPERLINK("url", "label") formulas in an image column are read as the link address.

= 2.1.10 =
* Fixed: CSV files saved in a regional code page, such as Excel's "CSV (Comma delimited)" on Windows, lost their accented, Cyrillic and other non-Latin characters during import; they were replaced with question marks while the import reported success. The importer now detects UTF-8, UTF-16, Windows-1251 and Windows-1252 files and converts them before reading.
* Fixed: CSV files saved by Excel as "Unicode Text" (UTF-16) were not recognised and showed no columns.
* Fixed: a semicolon, tab or pipe separated CSV imported as a single column when the delimiter was left at the default comma. The separator of the header row is now used in that case; a delimiter chosen explicitly is kept.
* Added: a "File encoding" choice on the upload step (Detect automatically, UTF-8, UTF-16, Windows-1250, Windows-1251, Windows-1252, ISO-8859-1, ISO-8859-2, ISO-8859-15) for files that detection cannot tell apart.
* Added: encoding and delimiter options in the Abilities API (parser_options in upload-complete, file-preview and import-prepare; encoding and delimiter in import-validate and import-start), so AI agents can import such files too.
* Fixed: when importing media, a file from another site with the same file name as an existing attachment could be treated as that attachment. Files from other sites are now compared by their content.

* Fixed: Elementor and Rank Math fields could fail to appear in the admin import mapping screen.

= 2.1.8 =
* Fixed: AI import preparation now automatically maps the Elementor Document Data column for posts and pages, including when Elementor is not active yet.

= 2.1.7 =
* Fixed: importing a post with a Cover block could corrupt the block's attributes, so the editor reported the block as invalid. The attachment ID in the block is now written correctly.
* Fixed: when an image in the content was already downloaded by an earlier step of the import, the Image block and its wp-image class kept the attachment ID from the source site. They now point to the attachment on this site, so WordPress can build responsive image sizes again.
* Fixed: imports wrote post content (after media processing) and custom fields without slashing them, so WordPress removed backslashes. Escaped quotes and \u sequences in JSON values or block attributes and Windows paths in text were damaged. Backslashes are now kept.
* Fixed: when importing a JSON or XML file, custom field values that are JSON strings (as stored by many page builders) were turned into arrays. They now stay strings. CSV and spreadsheet imports still restore arrays exported as JSON text.

= 2.1.6 =
* Fixed: in the Content Sync mapping dialog, clicking "Auto-match by Title" while the remote list was still loading could leave the button stuck on "Matching..." without matching anything. The button now stays disabled until the list has loaded, and only one match runs at a time.
* Fixed: the "Published" count in Browse Remote Posts included scheduled and private posts, so it did not match the list. Scheduled posts now have their own "Scheduled" filter and count.

= 2.1.5 =
* Fixed: AI agents could not finish preparing a Content Migration package through the Abilities API. The last response of rsl-ie/migration-prepare contained a field that was missing from the ability's output schema, so it was rejected. The admin screen was not affected.
* Fixed: a file uploaded in chunks over REST could not be completed with rsl-ie/upload-complete from a long-running process such as the WP-CLI MCP server (wp mcp-adapter serve). The process kept an old copy of the upload record and reported the upload as incomplete.

= 2.1.3 =
* New: Content Migration import now asks what to do with items that already exist on this site: skip them (default) or update them. Before, the migration screen always updated them, so pages with the same slug on the new site (for example shop or policy pages) were replaced with the version from the package.
* Improved: the migration result shows how many items were created, updated and skipped.
* Fixed: imports no longer request this site's own uploads over HTTP. With Replace URLs enabled and media not migrated in a separate step, these requests could wait for a free PHP worker and hold the import queue for minutes on hosts with few PHP workers, such as LocalWP. Files that exist on disk are now read directly.

= 2.1.2 =
* Fixed: with "Replace links" and "Automatically Import Media Files" both enabled, images inside post content were not downloaded. The link replacement already pointed them to this site, so they were treated as local files and left as broken images. They are now downloaded from their original address.
* Fixed: media files that could not be downloaded during an import (for example from a local development site the server cannot reach) were only written to the Jobs Log. The result screen now reports "Import Completed with Warnings" and lists the affected addresses with the reason.
* Fixed: the media summary in the Jobs Log counted 0 imported files when images in the content were downloaded.
* Improved: the last import step shows "Import Finished" instead of "Import in Progress" once the import is done.

= 2.1.1 =

Authors are now matched on the receiving site by email address, then by username. Updated posts keep their current author when no matching account is found, and accounts without permission to write posts (for example customers) are never used as authors. No user accounts are created.
* Fixed: a featured image transferred with Content Sync is now attached to its post in the Media Library instead of being listed as unattached.
* Improved: Jobs Log labels Content Sync jobs for pages as "Pages" (and "Blog Posts + Pages" for mixed jobs) instead of "Blog Posts".
