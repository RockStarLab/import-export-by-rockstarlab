# PHP_CodeSniffer Configuration

This project uses PHP_CodeSniffer (PHPCS) with WordPress Coding Standards.

## Configuration

File: `.phpcs.xml.dist`

### Standards Applied

-   **WordPress-Core** - Core WordPress coding standards
-   **WordPress-Docs** - Documentation standards
-   **WordPress-Extra** - Additional WordPress standards
-   **PHPCompatibility** - PHP 7.4+ compatibility checks

### What's Checked

✅ **Spacing & Formatting**

-   Spaces around operators
-   Spaces in control structures
-   Function parameter spacing
-   Proper indentation

✅ **Naming Conventions**

-   File names (lowercase with hyphens)
-   Class names (PascalCase)
-   Function names (snake_case)
-   Variable names (snake_case)

✅ **Documentation**

-   File doc comments
-   Class doc comments
-   Function doc comments with @param and @return

✅ **WordPress Specific**

-   Text domain usage
-   Deprecated function usage
-   Hook name formatting
-   Prefix validation (WP_AIE, aie)

### Running Checks Manually

```bash
# Check all files
./vendor/bin/phpcs

# Check specific file
./vendor/bin/phpcs path/to/file.php

# Auto-fix issues
./vendor/bin/phpcbf path/to/file.php

# Check with detailed report
./vendor/bin/phpcs --report=full
```

### IDE Integration

**VS Code:**
Install `phpcs` extension and configure:

```json
{
	"phpcs.enable": true,
	"phpcs.standard": ".phpcs.xml.dist"
}
```

**PHPStorm:**
Settings → PHP → Quality Tools → PHP_CodeSniffer

-   Set path to phpcs: `vendor/bin/phpcs`
-   Coding standard: Custom → `.phpcs.xml.dist`
